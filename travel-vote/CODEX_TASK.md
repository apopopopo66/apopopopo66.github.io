# Codex Task: Travel Vote mini app

## Goal
Build a reusable mobile-first voting page for choosing a group trip accommodation. Initial use case: 5 people choosing a sauna villa near Nokogiriyama, Chiba. The page will be shared in LINE.

## Deployment
- Existing GitHub Pages repo: `apopopopo66/apopopopo66.github.io`
- Implement only under `/travel-vote/` so the existing root site remains untouched.
- Target URL after merge: `https://apopopopo66.github.io/travel-vote/`
- Work only on branch `feat/travel-vote-app`.
- Do not merge to `main`.

## Tech choice
Prefer the simplest implementation that works well on iPhone Safari and LINE in-app browser.
- Static HTML/CSS/JavaScript is preferred; avoid a build step unless clearly beneficial.
- Supabase JS client for shared persistence.
- All Supabase config must be isolated in `travel-vote/config.js` and contain placeholders only in git.
- Never commit service-role keys or other secrets.

## Voting model
Use 5-star ratings rather than a single winner vote.
For each accommodation, each voter can rate 1–5 stars or leave unrated.
- A voter can update their own ratings later.
- Unique key: `(trip_slug, voter_name, accommodation_id)`.
- Show a Save button and clear success/error feedback.
- Do not require account login.

Results section:
- Average score per accommodation
- Number of voters who rated it
- Sort by average score descending, then vote count descending.
- Also show each voter's rating matrix if practical.
- Highlight the current top average visually, but do not hide other candidates.

## Supabase schema
Provide `travel-vote/supabase.sql` with schema and RLS policies.
Suggested tables:

```sql
create table accommodations (
  id text primary key,
  trip_slug text not null,
  name text not null,
  area text,
  price_total text,
  price_per_person text,
  sauna text,
  bbq text,
  access text,
  summary text,
  url text,
  image_url text,
  sort_order int default 0
);

create table votes (
  id bigint generated by default as identity primary key,
  trip_slug text not null,
  voter_name text not null,
  accommodation_id text not null,
  score int not null check (score between 1 and 5),
  updated_at timestamptz default now(),
  unique (trip_slug, voter_name, accommodation_id)
);
```

For this small friends-only app, anonymous read/write is acceptable. Add RLS policies scoped to these tables and document the tradeoff in README. Do not use service-role credentials in the browser.

## Acceptance criteria
1. Existing root GitHub Pages site is unchanged.
2. `/travel-vote/` opens without build tooling.
3. Works in iPhone Safari and LINE in-app browser.
4. User can enter a name, rate candidates, save, reload, and see persisted ratings once Supabase config is present.
5. User can modify their ratings.
6. Aggregated results update after save/refetch.
7. Missing Supabase config shows a friendly setup/demo state instead of crashing.
8. Prices are clearly marked as estimates.
9. No secret keys are committed.
10. README contains exact Supabase setup and GitHub Pages deployment steps.
11. Add simple smoke-test instructions and manually verify no console errors.
